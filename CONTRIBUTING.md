# Contributing to DexLadder

Thanks for wanting to help! DexLadder is one person's gift to the community, so contributions that scale best are:

- **Bug reports** — use the issue template; the in-app 🐞 button gives you a diagnostics line to paste.
- **Feature requests** — explain the learning value, not just the feature.
- **Docs & lesson feedback** — typos, unclear explanations, factual corrections in `docs/`.
- **Translations** — open an issue first; Hindi is the first target.

## Ground rules

1. Educational value first — DexLadder teaches, it doesn't advise.
2. Never real money — anything that touches real funds, keys with value, or paid services is out of scope, permanently.
3. Client-side only — features must work in one HTML file with no server.
4. Honest labels — anything simulated must say so.

## Code

The app ships as a single minified HTML file; the canonical source of truth is the deployed app itself (View Source). Substantive code contributions are best proposed as an issue describing the change; small self-contained patches can be attached to the issue.
